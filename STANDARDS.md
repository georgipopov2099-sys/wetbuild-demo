# WetBuild — стандарти за проекти

Този файл е reference за всеки нов WetBuild проект (основен сайт +
демота). Claude Code трябва да го прочете преди да започне нова
задача в тази папка или нейни поддиректории.

## Ценообразуване

- Основна валута: **EUR**, вторична **лв.** отдолу (по-малък шрифт,
  приглушен цвят), не обратното.
- Курс: `1 EUR = 1.95583 лв.` (фиксиран курс на БНБ).
- Пример: `199 €` голямо, `≈ 389 лв.` малко под него.

## Отзиви

- **Никога** не измисляй имена и цитати на "реални" клиенти в demo
  проекти — това е подвеждащо и създава лош прецедент.
- Отзиви в demo сайтове винаги са ясно обозначени placeholder:
  badge "PLACEHOLDER" + текст от типа "Тук ще стои реален отзив от
  клиент."

## Booking / резервации

- Не изграждай custom booking логика в demo фаза.
- Използвай placeholder контейнер с клас `calendly-embed`, готов
  да приема истински Calendly iframe embed по-късно, с ясен текст
  "Тук ще бъде вграден онлайн календар за резервации."

## Снимки

- За demo проекти без реален клиент: **безплатни снимки от Pexels**,
  сваляни ръчно и качени локално в `images/` — не hotlink (Unsplash
  Source е discontinued, не разчитай на него).
- Компресирай снимки преди commit — цел под ~2-3MB общо на страница.
  По-голям размер директно противоречи на "бързи сайтове" позиционирането.
- Никога не генерирай AI снимки на храна/хора за demo съдържание —
  изглежда изкуствено и подкопава доверието.
- **Ако проектът ползва реални снимки/лого на съществуващ бизнес**
  (напр. speculative redesign pitch): не публикувай на публичен
  GitHub Pages repo без съгласие от собственика. Ползвай Cloudflare
  Tunnel за временен private preview линк само за самата презентация.

## Уникалност между проекти

- Всеки нов проект трябва да има осезаемо различна визуална
  идентичност (палитра, шрифтове) **и различна структурна
  композиция**, не само различни цветове върху same skeleton.
- Избягвай да повтаряш едни и същи "signature" елементи между
  проекти: numbered section labels (напр. "01 — Услуги"), same
  badge-dot pattern, symmetric card grids по подразбиране за
  всичко.
- Преди да пишеш код за нов проект, провери структурата на
  предходните demo проекти в `demos/` и съзнателно вземи различни
  layout решения (asymmetry, различна навигация, различна
  композиция на секции).

## Контакт

- Винаги включвай телефон (`tel:` линк) **и** Viber бутон, не само
  email форма или контактна форма. Основната ЦА (собственици на
  малки локални бизнеси в България) предпочита обаждане/Viber пред
  писане.

## Достъпност

- Semantic HTML винаги (`<button>`, `<nav>`, `<header>`, не
  `<div onclick>`).
- Alt текст на всички снимки, на български, описателен.
- Достатъчен цветови контраст за текст.
- Видим focus state за keyboard navigation.
- Touch targets минимум 44×44px на mobile.

## Форми

- Валидирай на browser ниво: `required`, `type="tel"`,
  `type="email"` където е приложимо.
- Trim-вай input преди обработка (премахвай случайни spaces).
- Ясен feedback след submit (потребителят трябва да знае, че е
  проработило).

## SEO / meta

- Open Graph tags на всеки проект (`og:title`, `og:description`,
  `og:image`) — важно за preview при споделяне през Viber/Messenger.
- Favicon (емоджи или прост SVG достатъчен за demo фаза).
- Schema.org LocalBusiness structured data (JSON-LD) за реални
  клиентски проекти — пряко помага за Google Maps/local SEO
  resultати.

## Performance

- Lazy loading (`loading="lazy"`) на снимки под fold-а.
- Минимален брой external requests/шрифтове.
- Без frameworks (React, Vue и т.н.) без изрична конкретна причина
  — vanilla HTML/CSS/JS е default за всички WetBuild проекти.

## Технически конвенции

- Mobile-first, breakpoints ~600px и ~900px.
- Semantic, четим HTML/CSS — приоритизирай четимост пред клевърни
  трикове.
- Малки, проверими промени — не пренаписвай работещ код без причина.
